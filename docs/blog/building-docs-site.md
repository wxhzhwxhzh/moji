# 用静态文件搭一个文档站

![几层页面草图叠在一起、被一条线串起来的插图](../images/site-build.svg)

<!--META-->

这个站没有用前端框架。每篇文章是纯文本，构建时套上同一个外壳，输出一组 HTML 文件——就这么简单，改一个标题不需要重新学一套东西。

## 为什么不用框架

文档站的内容按周变化，交互只有“展开一行”和“打开一页”。为这点交互引入一整套运行时的成本，比它带来的方便更大。静态文件的另一个好处是：十年后它还是这样，不需要升级依赖。

## 三个部分

- 一份样式文件，所有颜色、字号、间距写成变量，改一处全站生效；
- 一个页面外壳：左侧目录、正文栏、左下角的反馈按钮；
- 一个构建脚本，把内容填进外壳，写到输出目录。

```
# 构建一次
npm run build

# 结果是一堆可以直接上传的静态文件
dist/
  index.html
  docs/getting-started.html
  blog/index.html
  assets/styles.css
```

## 把尺寸写成变量

正文栏宽、行高、列表每一行的高度，都是量出来的具体数字。写成变量以后，手机上只改几个变量就能收窄，不用逐条去调。数字记得写进注释，半年后你还知道它为什么是 26.67 而不是 26。

## 部署

> 静态站最省事的地方是没有服务器可挂：上传、缓存、回滚都是复制文件，出问题把上一次的文件夹放回去就行。

我把它放在一个对象存储后面，顺手打开压缩，首屏只剩两个请求。写完一篇文章，构建、上传，两分钟就上线了。
